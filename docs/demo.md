# 🎬 시연 시나리오 (5분)

> 강사님이 규칙 B1~B8을 직접 시험하는 W4 시연을 위한 문서입니다. 아래 순서대로 따라 하면 모든 규칙이 한 번씩 화면에 나옵니다.
> 이 시나리오는 가짜 데이터로 준비한 환경에서 **처음부터 끝까지 자동으로 따라 해 보았고, 확인 36개가 모두 통과**했습니다. (사람이 직접 눌러 보는 리허설은 시연 전에 한 번 더 해 보세요.)

## 1. 시연 전 준비

### 실행
`README`의 "실행 방법"대로 DB를 띄우고 앱을 실행합니다. (`docker compose up -d`, `./gradlew bootRun`, http://localhost:8080)
강사 계정은 `.env`의 `INSTRUCTOR_*`로 만들어집니다. 비밀번호는 문서에 적지 않으니 시연 환경의 `.env`를 확인하세요.

> **실제 학생 이름 · 학번 · 이메일은 쓰지 마세요.** 저장소가 공개라서, 아래 가짜 데이터만 사용합니다.

### 미리 만들어 둘 데이터 (가짜)

**학생 5명** (`/signup`에서 가입, 비밀번호는 시연용 임의 값으로 8자 이상)

| 학번 | 이름 | 이메일 | 시연에서의 역할 |
|------|------|--------|----------------|
| 20260101 | 한서준 | student1@demo.test | 제출 · 채점 완료 데이터가 있는 학생 |
| 20260102 | 이하윤 | student2@demo.test | 채점 완료 |
| 20260103 | 박지호 | student3@demo.test | 제출만 한 학생 (채점 대기) |
| 20260104 | 최서연 | student4@demo.test | **시연 주인공 (제출이 없음)** |
| 20260105 | 정민재 | student5@demo.test | 아무것도 제출하지 않은 학생 |

**강좌 2개** (강사 계정으로 개설)
- `자바스프링`: 학생 5명이 모두 참여코드로 수강 등록
- `데이터베이스`: **수강 등록한 학생이 없음** (B2 시연용)

**과제** (종료일시는 "지금 기준"으로 입력)

| 강좌 | 과제 | 시작 → 종료 | 비고 |
|------|------|-------------|------|
| 자바스프링 | 0주차 과제: 개발 환경 설정 | 10일 전 → 3일 전 | **마감** (B1 시연) |
| 자바스프링 | 1주차 과제: 변수와 자료형 | 2일 전 → 3일 뒤 | 진행중, 첨부파일 1개 |
| 자바스프링 | 2주차 과제: 조건문과 반복문 | 1일 전 → **20시간 뒤** | 진행중, **마감 임박** |
| 자바스프링 | 3주차 과제: 객체지향 | 2일 뒤 → 9일 뒤 | **예정** (B1 시연, 제출이 없어 삭제 가능) |
| 데이터베이스 | DB 1주차: 테이블 설계 | 1일 전 → 4일 뒤 | B2 시연용 |

**미리 낸 제출과 채점** (각 학생 계정으로 제출, 강사 계정으로 채점)
- 한서준: 1주차 제출(파일 첨부) → **92점** + 피드백, 2주차 제출
- 이하윤: 1주차 제출 → **78점**
- 박지호: 1주차 제출 (채점하지 않음)
- 최서연 · 정민재: 제출 없음

시연 직전 상태의 대시보드는 강사가 "내 강좌 2개, 진행중 과제 3개, 채점 대기 2건"으로 보이는 것이 정상입니다.

## 2. 시나리오 (약 5분)

> 주소의 숫자(`{과제 id}` 등)는 환경마다 다릅니다. 과제 제목을 눌러 열었을 때 주소창에서 확인하세요.

| 시간 | 계정 | 동작 | 기대하는 화면 | 보여 주는 것 |
|:----:|------|------|---------------|--------------|
| 0:00 | 강사 | 로그인 → 대시보드 → 강좌 관리 → `자바스프링` | 카드 3개와 최근 제출 표, 참여코드 · 수강생 5명 · 과제 표 | U2 · U3 · I1 · I2 · I3 |
| 0:40 | 강사 | 과제 등록 → 종료일시를 **시작일시보다 이르게** 입력 후 등록 | 종료일시 칸에 "종료일시는 시작일시보다 뒤여야 합니다." (입력값은 유지, 저장 안 됨) | **B7** |
| 1:10 | 학생 최서연 | 로그인 → 대시보드 → 내 과제 | 제출률 0.0%, 마감 임박 목록에 "2주차 과제", 상태 배지 진행중 · 예정 · 마감 | S2 · S5 |
| 1:30 | 학생 최서연 | 1주차 과제 → 제출하기 → 내용 입력 → 제출 | "제출했습니다." + 상태 "채점 대기" | S3 |
| 1:50 | 학생 최서연 | 다시 제출하기 → 내용을 바꿔 제출 | "다시 제출했습니다." + 바뀐 내용 (제출은 1건) | **B3** |
| 2:10 | 학생 최서연 | 0주차(마감) 과제를 열어 **제출 버튼이 없는 것**을 보여 준 뒤, 아래 3-1의 방법으로 강제 제출 | "제출 기간이 아닙니다." (3주차(예정)도 같은 방법으로 거부) | **B1** |

| 3:20 | 강사 | 최서연의 **채점** → 점수에 `150` 입력 후 저장 | 점수 칸에 "점수는 0 이상 100 이하여야 합니다." (저장 안 됨) | **B6** |

## 3. 규칙별 확인 방법

| 규칙 | 내용 | 화면에서 하는 방법 | 개발자도구로 강제하는 방법 |
|:----:|------|-------------------|--------------------------|
| B1 | 제출은 시작 ≤ 현재 ≤ 종료 일 때만 | 마감 · 예정 과제는 제출 버튼이 없음 | 3-1 |
| B2 | 수강 등록된 학생만 열람 · 제출 | 수강하지 않는 강좌의 과제 주소를 직접 입력 → 403 | 주소를 직접 여는 것이 곧 강제 요청 (개발자도구 불필요) |
| B3 | 과제당 학생 1건, 재제출은 덮어쓰기 | 같은 과제를 두 번 제출 → 제출 현황의 제출자 수가 그대로 | 3-1과 같은 방법으로 같은 과제에 두 번 보내도 1건 |
| B4 | 채점 완료된 제출은 재제출 불가 | 채점 후 과제 상세에 제출 버튼이 없음 | 3-1 (거부 문구가 "채점 완료된 과제입니다.") |
| B5 | 강사는 본인 강좌만 | 학생 계정으로 강사 화면 주소를 열면 403 | 3-2 참고 |
| B6 | 점수는 0 이상 배점 이하 | 점수에 `150` 입력 | 입력칸의 `max` 속성을 지우거나 값을 바꿔도 서버가 거부 |
| B7 | 종료일시 > 시작일시 | 과제 등록에서 종료를 시작보다 이르게 | 입력칸 값을 바꿔도 서버가 거부 |
| B8 | 제출이 있는 과제는 삭제 불가 | 제출이 있는 과제의 삭제 버튼 | 삭제 요청을 직접 보내도 서버가 거부 |

#### 3-1. 버튼 없이 제출 요청을 직접 보내기 (B1 · B3 · B4)

학생 계정으로 로그인한 상태에서, 아무 학생 화면의 개발자도구 **Console**에 아래를 붙여 넣습니다. `과제ID`를 대상 과제의 숫자로 바꿉니다.
(페이지에 있는 로그아웃 창의 CSRF 토큰을 이용해, 브라우저가 폼을 제출하는 것과 같은 요청을 보냅니다.)

```js
const f = document.createElement('form');
f.method = 'post';
f.action = '/student/assignments/과제ID/submit';
f.innerHTML = '<input name="_csrf" value="' + document.querySelector('input[name=_csrf]').value + '">'
            + '<input name="content" value="강제로 보낸 제출">';
document.body.appendChild(f);
f.submit();
```

요청이 서버에서 거부되면 과제 상세 화면으로 돌아오면서 빨간 안내(예: "제출 기간이 아닙니다.")가 보입니다.

#### 3-2. 한계 — B5(다른 강사 403)는 라이브로 보여 주기 어렵습니다

강사 계정은 가입할 수 없고 앱 시작 시 `.env`로만 만들어지므로, 보통은 강사 계정이 하나뿐입니다. 그래서 다른 강사의 강좌에 접근하는 것(403)은 **테스트로 확인**했습니다. (`./gradlew test`에 포함된 강좌 · 과제 · 제출 현황 · 채점 · 통계 테스트)
시연에서는 두 가지 중 하나로 대신합니다.
- 학생 계정으로 강사 화면 주소(`/instructor/courses/{id}`)를 열어 403을 보여 주기 (역할 접근 제한)
- 테스트 결과 화면을 보여 주기

앱 코드상으로는 `.env`의 `INSTRUCTOR_EMAIL`을 다른 값으로 바꿔 앱을 다시 시작하면 두 번째 강사 계정이 만들어지고(같은 이메일이 있을 때만 건너뜁니다), 그 계정으로 첫 강사의 강좌를 열어 보는 방법도 가능합니다. 이 방법은 **시연 환경에서 직접 확인하지 않았으니 리허설 때 먼저 해 보세요.**

## 4. 문제가 생겼을 때

| 증상 | 확인할 것 |
|------|-----------|
| 앱이 시작되지 않음 | DB 컨테이너가 떠 있는지(`docker ps`), 8080 포트를 다른 프로그램이 쓰고 있지 않은지 |
| 강사로 로그인이 안 됨 | `.env`의 `INSTRUCTOR_*`. 계정은 처음 한 번만 만들어지므로, 비밀번호를 바꿨다면 해당 계정을 지우고 다시 만들어야 함 |
| 마감 임박이나 "진행중" 표시가 시나리오와 다름 | 과제의 시작 · 종료일시가 입력한 시점 기준이라, 시연 당일에 가까운 날짜로 다시 만들어 두기 |
| 제출 현황 숫자가 다름 | 학생 5명이 모두 `자바스프링`에 수강 등록되어 있는지, 사전 제출 4건(한서준 2건, 이하윤 · 박지호 1건씩)이 맞는지 |
| 차트가 안 그려짐 | 통계 화면은 시작된 과제와 수강생이 있어야 차트가 나옴 (없으면 안내 문구) |
| 이미 시연을 한 번 해서 데이터가 달라짐 | 시연 주인공(최서연)의 제출은 한 번 채점되면 다시 제출할 수 없으므로, 새 학생 계정을 만들어 같은 순서로 진행 |

## 5. 알려진 한계 (시연 중 질문받을 수 있는 것)

- 제출 파일은 확장자만 검사합니다. 다운로드는 항상 내려받기로만 응답해 파일이 실행되지는 않습니다.
- 같은 제출을 두 사람이 동시에 채점하면 마지막 저장이 적용됩니다.
- 이의 신청 알림(강사 상단바 종 아이콘)은 화면을 열거나 새로고침할 때 갱신됩니다. 시연에서 학생이 이의를 신청한 뒤 강사 화면을 새로고침해 보여 주세요.
