# 요구사항 명세 (초안)

기능 ID(U/I/S)는 커밋 메시지·프롬프트 로그·평가표에서 그대로 사용합니다.
규칙 ID(B1~B8)는 [README](../README.md#비즈니스-규칙)의 비즈니스 규칙과 같습니다.

## 공통 (U)

### U1 학생 회원가입
- **입력**: 학번, 이름, 이메일, 비밀번호
- **처리**: 이메일 중복 검사, 비밀번호 BCrypt 암호화, role = STUDENT로 저장
- **결과**: 로그인 화면으로 이동 (`/login?signup`)
- **인수 기준**
  - 필수값이 비면 폼 에러 메시지를 보여 준다.
  - 이미 가입된 이메일이면 가입되지 않고 에러 메시지를 보여 준다.
  - DB에 저장된 비밀번호는 평문이 아니다.
  - 가입 화면에서 role을 지정할 수 없다 (항상 STUDENT).

### U2 로그인 · 로그아웃
- **입력**: 이메일, 비밀번호
- **처리**: Spring Security 폼 로그인(세션). 로그아웃은 POST `/logout`
- **결과**: 로그인 성공 시 `/`, 실패 시 `/login?error`, 로그아웃 시 `/login?logout`
- **인수 기준**
  - 로그인하지 않고 보호된 URL에 접근하면 `/login`으로 이동한다.
  - 로그아웃 후 뒤로 가기로 보호된 화면에 접근할 수 없다.

### U3 역할별 메뉴
- **처리**: 사이드바를 `sec:authorize`로 분기 (강사 / 학생)
- **인수 기준**
  - 강사에게는 강사 메뉴만, 학생에게는 학생 메뉴만 보인다.
  - 메뉴가 보이지 않더라도 URL 직접 입력으로 접근하면 서버가 403으로 막는다 (`/instructor/**` = INSTRUCTOR, `/student/**` = STUDENT).

### U4 강사 계정
- **처리**: 애플리케이션 시작 시 초기 데이터로 강사 계정 생성 (이미 있으면 건너뜀)
- **인수 기준**
  - 가입 화면으로 강사 계정을 만들 수 없다.
  - 초기 강사 계정으로 로그인하면 강사 메뉴가 보인다.

## 강사 (I)

### I1 강좌 개설
- **입력**: 강좌명
- **처리**: 참여코드 자동 발급 (형식은 [결정 사항](#결정이-필요한-항목) 참고), 로그인한 강사를 instructor로 저장
- **인수 기준**
  - 참여코드는 중복되지 않는다 (UNIQUE).
  - 강좌 목록에는 본인이 개설한 강좌만 보인다.

### I2 수강생 목록
- **처리**: 강좌 상세에서 enrollment 기준 등록 학생 조회 (학번, 이름, 이메일, 등록일)
- **관련 규칙**: B5 (본인 강좌만)
- **인수 기준**: 다른 강사의 강좌 상세에 접근하면 403.

### I3 과제 등록 · 수정 · 삭제
- **입력**: 제목, 내용, 시작일시, 종료일시, 배점, 첨부파일(선택)
- **관련 규칙**: B5, B7(종료 > 시작), B8(제출이 있으면 삭제 불가)
- **인수 기준**
  - 종료일시가 시작일시보다 이르거나 같으면 폼 에러.
  - 제출이 1건이라도 있는 과제를 삭제하면 "제출물이 있어 삭제 불가" 알림.
  - 다른 강사의 과제를 수정·삭제하면 403.

### I4 제출 현황
- **처리**: 과제별로 제출한 학생 목록과 **미제출자 목록**(수강생 − 제출자) 표시
- **인수 기준**: 수강생 3명 중 2명이 제출하면 제출 2명, 미제출 1명이 보인다.

### I5 채점 · 피드백
- **입력**: 점수, 피드백 코멘트
- **처리**: score, feedback 저장, status = GRADED, graded_at 기록
- **관련 규칙**: B5, B6(0 ≤ 점수 ≤ max_score)
- **인수 기준**
  - 점수가 범위를 벗어나면 폼 에러.
  - 채점 후 학생 화면에 점수와 피드백이 보인다.

### I6 통계 대시보드
- **처리**: 강좌별 제출률, 과제별 평균 점수, 미제출자 (group by 쿼리, Chart.js)
- **인수 기준**: 제출률과 평균이 실제 데이터와 일치한다.

## 학생 (S)

### S1 수강 등록
- **입력**: 참여코드
- **처리**: 코드로 강좌 조회 후 enrollment 생성
- **인수 기준**
  - 존재하지 않는 코드는 에러 메시지.
  - 이미 등록한 강좌에 다시 등록해도 중복 저장되지 않는다 (UNIQUE(course_id, student_id)).

### S2 내 과제 목록
- **처리**: 수강 중인 강좌의 과제만 표시. 상태 배지는 저장하지 않고 현재 시각으로 계산
  - 예정: 현재 < 시작일시 / 진행중: 시작 ≤ 현재 ≤ 종료 / 마감: 현재 > 종료일시
- **관련 규칙**: B2
- **인수 기준**: 수강하지 않는 강좌의 과제는 목록에도 상세에도 접근할 수 없다 (403).

### S3 과제 제출 · 재제출
- **입력**: 내용, 첨부파일(선택)
- **처리**: 서버(Service)에서 기간을 검증한 뒤 저장. 이미 제출이 있으면 새로 만들지 않고 덮어쓴다
- **관련 규칙**: B1, B2, B3, B4
- **인수 기준**
  - 기간 밖 제출은 화면 버튼과 무관하게 서버가 거부한다 (개발자도구로 강제 요청해도 막힘).
  - 같은 과제에 두 번 제출해도 submission은 1건이다.
  - GRADED 상태의 제출은 재제출할 수 없다.

### S4 결과 확인
- **처리**: 내 제출의 점수·피드백 조회
- **인수 기준**: 채점 전에는 "채점 대기", 채점 후에는 점수와 피드백이 보인다.

### S5 내 통계
- **처리**: 제출률, 평균 점수, 마감 임박 과제
- **인수 기준**: 수치가 실제 데이터와 일치한다.

## 결정이 필요한 항목

| 항목 | 추천안 | 확정 |
|------|--------|------|
| 참여코드 형식 | 6자리, 대문자+숫자(헷갈리는 O/0/I/1 제외), 중복 시 재발급 | 미정 |
| 첨부파일 저장 | 프로젝트 `uploads/` 폴더, 저장명은 UUID, 최대 10MB, 재제출 시 기존 파일 삭제 | 미정 |
| 상태 배지 | DB에 저장하지 않고 계산 | 미정 |
| 추가 컬럼 | [ERD 문서](erd.md#추가-컬럼-후보) 참고 | 미정 |
